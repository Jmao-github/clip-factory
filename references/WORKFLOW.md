# 长视频 → 精华短片 · 完整工作流 v3

**一句话**：一场 55–75 分钟 workshop 录制 → N 条 45–58 秒、可直接发布的短片。
机器时间约 50 分钟；负责人只 review 两处（选段方向 / 成片观感）。
**本文件是阈值与规则的唯一真相源**；选段判据细则 = `Clip Selection Rubric.md`，节奏实测基线 = `Pacing Baseline.md`，选段 prompt = `selection_prompt_template.txt`（同目录）。

v3 相对 v2 的三处结构改动（2026-09-13，源自 book-video 开源工作流对照）：
1. **专名表前置**（阶段0）：转写前先建 `glossary.json`，主动预防字幕品牌名错，不再事后 SUBFIX 补漏
2. **最窄重跑**：`ONLY=<slug>` 只重建/重查单条并合并写回，不再全量推倒
3. **候选片保护**（promote 门）：成片先落 `{slug}.cand.mp4`，全 gate 绿才由 `promote.py` 替换正式片

## 阶段 0 · 取素材 + 专名表

| 来源 | 用途 | 坑 |
|---|---|---|
| Google Drive 录制 | 唯一视频源 | 「查看者不可下载」时**按账号逐个试**（用有访问权的那个账号；`/u/N` 槽位映射会漂移不可信） |
| 会议纪要（Granola 等） | 内容地图 + 讲者边界线索 | 转写质量差（品牌名→音近词、讲者姓名→音近错拼），**永不用于切点/字幕** |
| 本地 mlx-whisper | 词级时间戳 | 切点与字幕唯一真相源；56 分钟 ≈3 分钟，零成本 |

**专名表（v3 新增，主动预防）**：从活动页/Granola/讲者自介收齐本场**讲者名、产品名、品牌名、术语**，写 `WORKDIR/glossary.json`（`{"错听形":"正确形"}`）。whisper 转写完成后立即用表扫全文补录新错听形。用途：① overlay.py 字幕修正（合并进 SUBFIX，场表覆盖默认表）② 选段 prompt 的品牌名提示段。历史必错例：treg→track/trag、Ahrefs→href、Qwen3→Quint3、Modal→model、hyperframe→HyperFrame、crocs→crux。

## 阶段 1 · 三路扫描

- **whisper**：`word_timestamps=True` 覆盖全片
- **气口表**：`silencedetect` -32dB / 0.4s
- **画面**：帧差 scene>0.12 变化点；**布局探测** = 右上角 `crop=80:100:1200:20` 灰度**均值 < 20** 为共享屏、≥20 为纯摄像头——⚠️讲者背后有暗窗会骗过阈值（0816 实翻），最终 layout 以 faceMap+人眼为准，spec 里 `layout_force` 指定
- **faceMap（0915 新增，负责人批准 <$3/场）**：`facemap.py` 用 **gemini-3.1-pro（1M context）整段看完源视频**，出 facemap.json 时间表：每个区间的布局 + 每张人脸的位置与种类（Meet 摄像头格 / **悬浮在共享内容里的自拍小窗** / 全屏人像）+ 有无第二人。剪辑照表定 `layout_force` 与 `pip` 开关——**单讲者共享屏=画面上只准有一个头像**（0913 铁律），源自带自拍窗则 `pip:false`

## 阶段 2 · 内容筛选（负责人点名最重要的一步）

**只用文本判断，不看视频。** 全文（句子级+时间戳）一次性喂给评分器读完再输出，不抽样、不依赖 AI summary。Prompt 用 `selection_prompt_template.txt` 填空。

**五项判据**（1–5 分）：
| 判据 | 问的是 |
|---|---|
| `lesson` | 可迁移的做法/判断，还是"某工具好用"？**工具会过时，教训不会** |
| `useful` | 看完能不能改变明天的做法 |
| `shareable` | 有没有一句可被单独引用、反直觉或带数字的话 |
| `standalone` | 脱离这场还成不成立 |
| `not_promo` | 讲者卖自己产品降权（宣传片任务时豁免此项） |

**硬门槛**（不满足直接出局）：段内自洽无外部指代 · 无悬空承诺 · 无粗口/demo 翻车 · 非多人抢话 Q&A · 可裁到 45–58s。

**亮点与节奏两条加权规则**（细则与实测依据见 `Clip Selection Rubric.md` §0/§0b + `Pacing Baseline.md`）：
- 留存法则：第 0 秒即全片最强论断；前 10 秒必须交付完整观点（10 秒流失一半观众）；钩子 ≤7s
- ~~视觉节奏门槛（运动能量筛 ≥0.04）~~ **2026-09-15 对「单讲者+共享屏 workshop」片型停用**（负责人拍板）：这类片画面最活跃常是翻网页找链接，安静讲 slide 的金句反而能量低——能量只留作决策表参考列，不参与筛选

**病毒信号参考列（0915）**：8 类信号（hook/emotion/opinion/revelation/conflict/quotable/story/practical，源 AI-Youtube-Shorts-Generator）+ 0-100 viral 分——**只报告不计入 total**，用于收敛候选间二选一和文案钩子；排序仍以五判据为准。

**三方互证**：Gemini 池 + GPT-5.2 池（同判据、独立模型）+ OpusClip 候选。三方都指向的段=放心剪；分歧=留记录给负责人。

## 阶段 3 · 出片

### 3.1 切点（词边界，永不切进词内部）
- 起点留 0.25s 呼吸、终点留 0.30s；连续语流无气口时向前/后借 0.06s 保字头字尾
- 削词判定：切点吃进一个词超过 0.10s = FAIL；出点压在词起点（整词丢失）= FAIL

### 3.2 顺滑层（Descript 式，分级压气口）
| 位置 | 上限 |
|---|---|
| 句末 `.?!` 后 | 0.55s |
| 逗号/从句后 | 0.32s |
| 词间犹豫 | 0.18s |
| uh/um/erm | 整词删除 |
碎片 <0.06s 不成段。只删整词和静音。
**声学精修（0915 晚·负责人抓残响后立）**：whisper 给 filler/词尾标的时间可漂 0.3-0.8s，纯按词表切必留残响或切词。每个拼接点按真实波形修：① 起点=发声块模型（扫 [s, 词标+0.9s] 发声块，词块=第一个延伸过词标+0.08s 的块，起点=词块前 ≤0.10s 且不早于上一块结束——残响块整段排除）② 删过 filler 且下一词辅音开头、词块头却是 ≥0.10s 低ZCR元音 → 元音段=粘连 uh，切到辅音过渡点（ZCR≥0.3 或 RMS 谷；911.64 'uh-so' 案）③ 终点=顺声延伸至静音谷 ≤0.30s（防切词尾）。真相源=RMS(20ms窗,阈0.012)+ZCR(阈0.25/0.30)。

### 3.3 机位（零推近；高亮绿框 2026-09-06 负责人拍板永久禁用，F 机位废除 F→W）
- 两套布局自适应：共享屏恒为**内容 + 右下 PIP 人脸**（有 slide/内容时内容和人脸必须同在）；纯摄像头 `CAM→CAMF→CAM`（整帧不叠 PIP）
- **零像素推近**：720p 源共享区只有 960×488 像素，任何输出路径有效放大 ≤**1.34×**（全景 1280/960=1.33 封顶）
- 每个机位**至少停 6 秒** · 禁乒乓 · 机位边界取总长 **28% / 72%** 处吸附到句子边界 · **屏幕内容与口播相关时禁用人像大画面**（会挡金句）
- 人像窗：`crop=320:180:960:270` 缩到 256px 右下角；纯人像模式放大 520px 上限（原生 320px，再大就糊）
- **缓推抖动根治（0915 晚，负责人抓的）**：zoompan 只能整像素步进，慢推时 x/y 各自隔十几帧跳 1px，密集文字上读作镜头抖 → **4x 超采样(5120×2600)进 zoompan 再 lanczos 降回**，步进精度 1/4px（帧间差峰值 8.58→3.41，2x 放大人眼不可辨）。代价：处于亚像素相位的帧 Laplacian 略低于整像素帧（x0.90-0.97），是消抖的固有对价非损质，锐度回归见低点先亲眼比帧再判
- **每观点段一个镜头（0915）**：缓推（94%→100%，pad+虚化边+zoompan）**按观点段重置**——每条片由 2-3 个观点段拼成，每段起幅收 94% 推到满，段边界=天然换镜头感；spec 每 seg 配英文 `label`，**标签卡跟观点段切换**（不再绑机位/28%-72% 任意边界）
- 标签卡文本：优先 spec 每 seg 的 `label`（每段英文标题）；旧 clip 级 `labels` 字段仅作回退

### 3.4 编码（单代有损）
- 全链 **lanczos** 缩放 + 全景路径 unsharp 5:5:0.35 轻锐化
- 中间件**无损**（x264 qp0 → High 4:4:4 profile 可验证）→ concat copy → 字幕层合成时**单代 crf16**/preset slow
- 主裁切 `crop=960:488:0:132`（去菜单栏/Dock/黑边）
- 产出 = `{slug}.cand.mp4` 候选片；**正式片 `{slug}.mp4` 只能由 promote.py 替换**

### 3.5 字幕与图形
- 字幕：Arial Bold 44px 白字 3px 黑描边，底部居中 ≤2 行；每屏 **≥5 词且 ≥1.1s** / 或 **≥1.9s** / 或句末即断屏；**词间空隙 >0.5s 强制断屏**（否则静音被算进字幕时长）；硬上限 2.6s/屏
- **字幕底带自动判定（0915）**：每屏字幕在 base 帧检测落区「暗底(均值<105)+含白字(>200 亮点占比>1.2%)」→ 自动垫深色底带；纯亮底（幻灯片）不垫。`cap_backdrop` 保留为整片强制开关
- **字幕专名修正 = 默认 SUBFIX + 本场 `glossary.json`**（场表覆盖默认表），只改字幕不动音频
- 标签卡：左上 **Arial Bold 30px** 深底绿字，跟内容段切换（补"内容在变"的节奏缺口）

### 3.5b 中间件与时间轴（v7，codex 实验室对照落地）
- **中间音频 PCM 无损**（pcm_s16le .mov），全链只在成片终压一次 AAC——此前中间件 aac=音频双代有损
- **剪口吸附 24fps 帧边界**：一条时间轴同时供视频/音频/字幕，根治逐段小数秒累积的音画时长漂移（修后 A/V Δ=AAC 封装固有 ~30-90ms）
- **每段几何参数化**：spec segs 可设 layout(screen/camera)/pip/pip_rect/screen_rect，缺省保留原行为——布局漂移场（0816类）不再改代码
- **脚本从引擎目录统一解析**（run_pipeline ENGINE 定位 + sys.executable），workdir 只放素材，不再撒脚本副本
- **splice 空词表=硬失败**（曾因 lwords 丢失而空转盖章，codex 负向对照抓出）；splice 新鲜度对 base 比（其审计对象是剪口非成片）
- **粘连uh判定加发声起点条件**：起声≈词标±0.05=词自身浊音头（the/ð、but/b 案），真粘连=发声明显早于词标——首字母辅音表误报根治

### 3.5c 字幕保真三条（v8，0915 晚「一场扩到 5 条」时实证抓出，波及此前全部成片）
- **词→字幕的映射按重叠判据，不按严格包含**：旧实现要求词的 start/end 都严格落在 span 内，凡被 24fps 帧对齐或声学起点模型削掉几十毫秒的词，**整词从字幕消失而音频里还在**（实证：字幕出现 "everyone said it is but for character design"，"best." 没了但音频覆盖 0.37/0.38s）。判据改为「重叠 ≥35% 词长或 ≥0.15s 才算在片内」并把时间夹紧到 span。回归对照：五条全部只增不减（+8/+4/+1/+6/+5 词，零删除）。
- **专名表在词序列上替换，不在单屏文本上**：旧做法对每屏字幕 re.sub，品牌名一旦被切到两屏就整条失效（实证 "GP image 2 .5" 被切成 "The GP image 2" / ".5 on the internet"）。同时把 whisper 拆出的 `2`+`.5` 先并回 `2.5`。多词表项（`11 lab`/`byte plus`/`GP image 2.5`）全靠这条才生效。
- **口头禅永不上字幕**：宽松映射会把剪口残片捞回字幕（实证：G11/G12 两道声学 gate 都判该剪口干净，字幕却冒出 "Uh,"）。token 级 filler 过滤只动字幕、不动音频。

### 3.6 执行器 / 语速 / 运动（v5，负责人拍板「产出稳定是关键」）
- **一键执行器 `run_pipeline.py`**：build→splice(G12)→overlay→rt2(串行!)→boundary(G11)→greenbox→loudness→av→vision 一条命令，失败停下指名 clip+gate；到人裁签字为止，promote 由人签后单独跑。rt2 永不与重负载并发（并发会出 whisper 假 FAIL，实翻）
- **语音加速**：spec 每条 clip 可设 `tempo`（1.0–1.15，atempo 变速不变调），字幕/标签时间轴同缩；0906 clip1 实测 1.06 全 gate 绿
- **运动词汇**：spec 每 seg 可设 `motion`: in推近(默认)/out拉远/hold稳住；缓推=smoothstep 缓入缓出，垫边=重度压暗防人脸模糊分身（同人双头像硬事故）

## 阶段 4 · 验证闭环（全 gate 机检）

| # | 检查 | 判据 | 证据文件 |
|---|---|---|---|
| 1 | 词完整性 | 应保留词 100% 覆盖、0 削半、0 整词丢失 | built.json `integrity` |
| 2 | 分块重转写 | 30s 分块（整文件会尾部幻觉）；相似度 ≥0.85 + 首尾锚点（序列 0.70 或内容词 75% 模糊命中） | retranscribe.json |
| 3 | 图文一致性 | 每段 25/50/75% 三帧 × Gemini 严判"具名主体不符"，多数决；新场景先过正负对照验判别力 | avcheck_out.json |
| 4 | layout | 机位/乒乓/字幕时长全量复核 | layout_audit.json |
| 5 | 内容 | 有可引用论断、无粗口、开头非悬空连接词、每段有 why | 决策表 |
| 6 | 锐度回归 | 重渲类改动必须在抽样帧上 Laplacian 方差全点数 ≥ 旧版 | sharp 输出 |
| 7 | 说话人 | 归属按内容证据（自报名/自家产品交叉验证）定边界 | 决策表 |
| 8 | 绿框根除 | 成片全程 2fps 扫绿框色签名 (120,230,160)±28，>8000px 判 FAIL | greenbox_result.txt |
| 10 | 响度 | 集成响度 −16±1 LUFS 且真峰值 ≤−1.0 dBTP（EBU R128，源 autocut 同域实测值；overlay 两遍式 loudnorm 线性应用） | loudness.json |
| 9 | 成片视觉审查 | ≤2.5s 间隔全程抽帧→网格→Gemini 毙稿官逐格严判 + **本人逐格亲眼终裁**；人裁结论写 final_vision_review.json 的 `clips_pass` 列表 | vision_gemini.json + final_vision_review.json |
| 11 | 边界词完整（0915 晚，负责人抓「perfect 被切没」+「接口残留 uh」后立） | 对成片每个接口（观点段边界+片头片尾）±2.5s 窗口机器耳重转写：上段末词在、下段首词在、接口 ±0.45s 无独立 uh/um；负向对照已验（旧坏片确实检出缺词） | boundary_check.json |
| 12 | 拼接点残响声学审计（0915 晚，负责人抓「clip2 每个剪口都有 uh」后立；⚠️ whisper 对残响是聋的—转写检测负向对照全 miss，必须查波形） | 每个 keep-span：A) pre-roll 到词真实起声点之间 ≥0.04s 发声=残响 FAIL；B) 删过 filler+下一词辅音开头但 span 头是 ≥0.10s 低ZCR元音=粘连uh FAIL；负向对照命中负责人报的全部时间点 | splice_audit.json |

**FAIL 处置（v3）**：每道检查指名 clip+gate → 修内容后 `ONLY=<slug>` 窄重跑该条（build/overlay/rt2/vision_review 均支持，结果合并写回不覆盖他条）→ 重查后再过 promote。不放宽规则。

**promote 门（v3）**：`ONLY=<slug> python3 promote.py`——核对 gate 1/2/3/8/9/10 证据 + 证据新鲜度（所有证据 mtime ≥ 候选片 mtime，防拿旧检查放行新片），全绿才 `cand → {slug}.mp4`；任何缺证/失败/过期打印指名清单并退出非零。旧有效成片在 promote 前绝不被触碰。

## 阶段 5 · 交付

## OpusClip 的位置（三连实测结论，2026-09-06）

**判断层自持，渲染层也不用。** Pro $29/月（key 放 `OPUSCLIP_API_KEY`，API 月额 900 credits，一场 55 credits≈$5.3）。

## 已知弱点（不粉饰）

1. **720p 源片是物理天花板**——管线自身损失已清零，再往上要录制方提高录制清晰度。兜底：锐度回归 gate 防倒退。
2. **图文一致性只看每段 3 帧**，整段扫描成本高。兜底：G9 成片视觉审查 ≤2.5s 全程抽帧兜住渲染事故；可疑段人工抽帧复核。
3. **两个评分器的判据文本仍出自我手**。兜底：两榜独立跑、分歧留档，仲裁人是负责人。
4. **顺滑层只在英文单人讲解上验证过**。兜底：硬门槛先把多人抢话素材挡在外面。
5. **45–58s 区间来自广告素材基线**，非社区实测。兜底：等发布数据回来校准。
6. **说话人靠内容推断非声纹**。兜底：交接句+自家产品交叉验证+机检边界。

7. **whisper 整片词时间戳在口头禅密集区可漂 ~0.8s**（0915 实翻：切点按其词尾+0.06 把 'perfect' 整个切没，负责人耳朵抓的）。⚠️ 短窗局部重转写不是解药——它会漏写 uh/um（口头禅删不掉）且窗尾幻听（已试已撤）。对策：① 选段切点绕开口头禅密集/自我修正区（宁可换收口句）② G11 boundary_check 机器耳兜底验每个接口。


## 阶段 4 补充 · 两类「机器耳抓到、肉眼抓不到」的切点陷阱（0915 晚实证）

- **whisper 会把极短功能词标成 0.0x 秒**（实证 26:38.26 的 "I" 只有 0.04s）。以这种词做片头，声学起点模型必然落进词内，成片机器耳只听到下一个词 → G11 FAIL。**片头/段首别挑单音节功能词**，挑实词。
- **段首挑弱读连接词（but/and/so）同样危险**：起声在词内，G11 FAIL。挑发声明确的实词起段。
- **补时长优先靠加内容段，不靠往前借半句**——两次回退都是往前借半句借出来的。
