# 选段判据卡 v3

v1 → v2 的改动来自三个来源：负责人的反馈、投放留存数据、Gemini 独立评审。**新增的都是"重点分层"相关的硬规则。**

## ⭐ 0. 留存法则（v2 新增 · 最高优先级，压过其他一切偏好）

来自 TikTok 广告库前 20% 素材的 9 条真实逐秒留存曲线：

| 时间点 | 剩余注意力 |
|---|---|
| 3 秒 | 峰值 100% |
| 10 秒 | **约 50%** |
| 20 秒 | 约 35% |
| 60 秒+ | 约 22%，之后走平 |

推论，直接作为硬规则：

1. **第 0 秒就是全片最强的那句论断。** 不许有铺垫、不许有"今天我想聊聊…"、不许有自我介绍、不许描述现象（"最近大家都在讨论X"）。
2. **前 10 秒必须已经交付一个完整的观点**，不是抛出一个话题。
3. **能活过 20 秒的观众基本会看完**——所以 20 秒之后可以放长论证，前 20 秒必须是纯浓缩。
4. 排序不再是"按原片时序"，而是**按论断强度**：最强的先给。（v1 的"不重排"规则被本条推翻。）

## ⭐ 0b. 视觉节奏门槛（v3 新增 · 实测依据在 Pacing Baseline.md）

参考片实测：平均 **2-6 秒**一次画面变化，**前 20 秒 7-10 次**，最长静止镜头 3.2-4.5 秒。
我们 v2 实测：平均 **25.5 秒**，前 20 秒 **0 次**。差距 10 倍。

1. **候选段必须先过运动能量筛**：30 秒窗口的平均 scene score ≥ 0.04 才进候选池（我们 v2 用的区间是 0.006-0.036，属于全片最静）。
2. **但高能量 ≠ 好内容**：全片能量最高的两个窗口（3:00 / 5:30）是他在翻推特找链接，属硬门槛第 4 条排除项。**能量是筛子不是选择依据**，两个都要过。
3. **cut-in 在这份素材上无效**，别再试：白板缩放 210-286%，内容填满画布，收紧就切字（已实测，16 块里仅 2 块可用）。要节奏只能靠选段或引入设计元素（后者负责人尚未批准）。

## A. 硬门槛（不满足直接淘汰）

1. **自洽**：不看前后文能听懂，段内无指向段外的代词。
2. **不切在半截**：起止落在完整句边界 + 真实静音。词级时间戳校验，任何被削掉半个词的切点判失败。
3. **无悬空承诺**："I will show you an example" 而例子不在段里 → 淘汰。
4. **画面可读**：手写白板 ✅ / 代码文档 ⚠️ / 找文件切窗口的过程 ❌。
5. **无长静默、无口误重启。**

## B. 选段偏好

0. **钩子这一拍 ≤ 7 秒**（参考片实测 4-10 秒，中位数 5 秒），且钩子内必须已出现"结果"或"反常识断言"，不能只抛话题。v2 的钩子是 13.7 秒的单句，超标一倍——但那是一整句话，不切坏就压不下去，属素材限制。
1. **有起因有结论**：完整论证单元。
2. **有信息增量**：能被引用的判断，不是背景铺垫。
3. **收口有力**：落在判断句，不落在连接词或提问。
4. **优先讲者独白**，多人交叉对话降权。
5. **口播与画面冗余时，砍口播留画面。**（v2 新增。实例：白板已写 `Time-based / Goal / Event-based → Agent`，口播逐个举例就是冗余，直接跳过，拼接处听不出来。）
6. **砍掉不确定性表述**："我不知道有多少人在做这个"、"我可能记错了" —— 削弱权威感且不带信息。（v2 新增）

## C. 合集组装

1. **按论断强度排序，不按原片时序**（v2 修订）。
2. 段间硬切，不加转场。
3. 结尾段可以很短（<10s），职责是收成结论。
4. **总长目标 90–120 秒**（v2 修订，原为 3 分钟）。3 分钟以上只在内容本身极强时才允许。

## D. 画面处理（v2 定案）

**默认开启静态裁切**（一个死框，全片不动，不是 zoom 不是跟踪）：
- 主画面 `crop=960:488:0:132` → 去掉 macOS 菜单栏 / 浏览器标签栏 / 书签栏 / Dock / 右侧 320px 黑边
- 人像 `crop=320:180:960:270` 缩成 256px PIP 放右下角
- 输出 1280×650

依据：Gemini 独立评审判定视觉噪音伤害 8/10，杂物占近 30% 画面。裁切是零风险的（全片窗口布局一致，已抽帧核对）。
**仍保留全画面版本供对比** —— 最终用哪个由负责人定。
